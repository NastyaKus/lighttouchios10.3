# Ember VM 0.2.1 — повтор после прерывания

Подтверждён по коду вторичный сбой: оставшийся после завершения процесса
restore-running запрещал повтор, а монитор выводил старую консоль. Само это
сообщение не устанавливает причину первого исчезновения процесса на телефоне.

Изменения:
- OS lease с автоматическим освобождением при смерти процесса вместо проверки
  наличия marker; lock находится в private filesDir.
- Повтор из уже подготовленного набора с подтверждением очистки staged-дисков.
  Исходная копия IPSW, активный набор и подготовленные компоненты сохраняются.
- Архив последних трёх наборов диагностических журналов перед повтором.
- Экспорт диагностического ZIP через Android CreateDocument без компьютера.
- История завершения процессов Android 11+, Java crash log и журнал управляемых
  остановок VM; полный stack trace ошибок восстановления.
- Защита кнопки от повторного нажатия во время передачи команды запуска.
- Возврат на экран результата в main-процессе при обработанной ошибке.
- Исправлена ссылка Apple Wiki на AzulSeed 18A5351d.

Проверки добавлены для stale-marker, live-lock, принудительного завершения
реального дочернего процесса с lock, сохранения журналов без Apple inputs,
отказа при отсутствующем IPSW до очистки диска. Android экспорт и причина
первого вылета требуют диагностического файла с телефона.

Обновление имеет тот же applicationId dev.embervm.android и подписывается
тем же debug certificate, что APK 0.2.0 этой сессии. Удалять приложение перед
обновлением не нужно.

Уточнение пользователя: сообщение о прерванной попытке появилось при первом
нажатии восстановления. Нельзя считать доказанным предшествующий вылет гостя;
происхождение marker и причина завершения процесса требуют диагностики.
